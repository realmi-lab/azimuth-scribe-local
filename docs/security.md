# Mac 본인 인증과 암호화 보관함

1.3.0부터 **Touch ID 또는 Mac 로그인 암호로만** 보관함을 엽니다. Mac 앱의 두 버튼 중 하나를 누르고 macOS 인증창에서 인증하세요. 별도 앱 비밀번호, 비밀번호 저장 선택, 브라우저 로그인은 제공하지 않습니다. Mac 로그인 암호의 길이·변경 정책은 macOS가 관리하며 앱은 이 암호를 받거나 저장하지 않습니다.

브라우저의 `http://localhost:18765`에는 Mac 앱 열기 안내만 표시됩니다. 앱은 같은 localhost 서버를 내부 WKWebView로 사용합니다.

## 인증과 키 보관

- 잠금을 열 때마다 새 LocalAuthentication 문맥으로 인증합니다. Touch ID는 생체 인증 정책을 사용하며 지문 재사용 시간을 0으로 설정합니다. Mac 암호 버튼은 `devicePasscode` 제약으로 로그인 암호를 요구합니다. Apple Watch와 별도 앱 암호로 여는 경로는 없습니다.
- 인증 성공 후에만 로그인 키체인의 무작위 256비트 비밀값을 읽습니다. 새 보관함은 이 값을 생성해 키체인에 저장하고 읽기 검증을 마친 뒤 만듭니다. 인증 취소·실패·키체인 오류 시 열지 않습니다.
- 이 로컬 빌드는 Apple 개발자 프로비저닝 프로파일 없이 ad-hoc 서명합니다. 파일 기반 로그인 키체인과 앱 접근 목록을 사용하며, 앱 코드가 키체인 읽기 전에 시스템 인증을 확인합니다. Secure Enclave나 Data Protection Keychain이 항목 접근을 강제하는 구현은 아닙니다. 재설치로 서명이 바뀌면 macOS의 키체인 접근 확인이 추가로 나타날 수 있습니다.
- 키체인 비밀값은 HTTP·명령행·환경 변수·로그로 전달하지 않습니다. 소유자만 접근하는 Unix 소켓으로 전달하고, 서버가 커널에서 받은 상대 UID·PID, 설치된 앱 실행 경로와 코드 서명을 확인합니다. HTTP의 기존 설정·비밀번호 로그인 API는 `410`으로 거절합니다.
- 인증된 세션만 앱 메모리와 임시 WKWebView의 HttpOnly 쿠키에 둡니다. 브라우저에는 세션을 전달하지 않습니다. 상태·파일 목록·다운로드 API는 유효한 세션이 필요합니다. 잠금 시 기존 세션을 폐기하고 진행 중 다운로드도 중단합니다.

## 저장과 잠금

- 녹음이 끝나면 WAV를 암호화해 보관합니다. 복호화한 복사본이 원본과 같은지 확인한 뒤 평문 임시 파일을 지웁니다.
- 받아쓰기, 요약, 파일 목록, 사용자 서식, 일괄 수정 규칙도 암호화합니다.
- AES-256-GCM을 사용합니다. 파일마다 무작위 128비트 salt와 HKDF-SHA256으로 별도의 키를 만들고, 1 MiB 단위로 인증해 오디오를 탐색합니다. 헤더, 상대 경로, 보관함 ID, 블록 순서도 인증합니다. 암호 알고리즘은 `cryptography` 라이브러리를 사용합니다.
- 무작위 256비트 보관함 키는 키체인 비밀값에서 scrypt로 파생한 키로 감싸 `vault.json`에 저장합니다. 평문 키와 키체인 비밀값은 이 파일에 들어가지 않습니다.
- 재실행하면 항상 잠깁니다. 세션은 메모리에만 있고 잠그면 모두 폐기합니다. 상태·파일 목록·다운로드 API도 세션을 요구합니다.
- 5분 동안 사용하지 않으면 잠깁니다. 화면 잠금·사용자 전환·절전 시 Mac 앱도 잠금을 요청합니다. 모델 작업 중에는 유휴 잠금을 미룹니다. 명시적인 잠금은 작업을 중단하고 저장을 마무리한 뒤 키를 해제합니다.
- 음성 인식과 다운로드는 암호화 파일을 메모리에서 읽습니다. STT를 위한 평문 디스크 사본은 만들지 않습니다.
- 결과 저장은 기본적으로 암호화 보관만 합니다. **일반 파일도 내보내기**를 선택하면 암호화가 해제된 TXT·MD를 별도로 저장합니다. 녹음 목록의 일반 음성 내보내기도 같은 원칙입니다.

## 기존 데이터와 백업

이전 버전에서 키체인 연결을 저장했다면, 첫 Mac 본인 인증 후 이전 연결을 읽어 새 키체인 비밀값으로 보관함 키를 다시 감쌉니다. 보관함 ID와 실제 데이터 키는 유지하며 기존 `.enc` 파일은 다시 암호화하지 않습니다. 새 키체인 저장·검증을 먼저 완료하고 메타데이터를 원자적으로 교체합니다. 실패하면 기존 파일을 보존하며 이전 앱 비밀번호를 입력받는 대체 경로는 제공하지 않습니다.

이전 키체인 연결이 없는 보관함은 전환을 중단합니다. 해당 보관함을 만든 이전 버전에서 키체인 연결을 마친 뒤 업데이트해야 합니다. 과거 백업을 위해 이전 키체인 항목은 남겨 두지만, 이전 비밀번호로 새 `vault.json`을 열 수는 없습니다.

최초 설정이나 재개 시 기존 파일을 암호화한 뒤 내용 해시를 대조합니다. 검증이 실패하면 원본을 보존합니다. 이관 도중 종료되어 원본과 암호화 파일이 함께 남으면 다음 잠금 해제 때 검증을 재개합니다. 내용이 다르면 자동으로 덮어쓰거나 지우지 않습니다.

서버를 중지하고 **`vault.json`과 `.enc` 파일을 포함한 `data/` 전체**를 백업하세요. 복원에는 그 보관함 ID에 연결된 **Mac 키체인 항목도 필요합니다**. 데이터 폴더 사본과 Mac 로그인 암호만으로 다른 Mac에서 열 수 없습니다. 키체인이 자동으로 이전될 것이라고 가정하지 마세요. 현재 버전에는 복구 키 내보내기나 암호 분실 시 우회 기능이 없으며, 키체인 항목을 잃으면 복구할 수 없습니다.

## 보호 범위

이 기능은 **보관된 암호화 파일만 복사해서 가져간 경우**에 대비합니다. 다음은 보호 범위에서 제외합니다.

- 녹음 중인 `pending-recording.m4a`, 업로드·형식 변환 도중의 임시 파일. 비정상 종료 시 평문이 남을 수 있습니다.
- 가져온 파일의 원래 위치, 예전 소스 폴더의 `data/`, 과거 백업·스냅샷, 일반 파일로 내보낸 사본. 다른 위치의 파일은 자동으로 지우지 않습니다.
- 삭제한 평문의 저장 장치 잔여 흔적. 파일 삭제는 SSD의 물리적 완전 삭제를 보장하지 않습니다.
- 잠금 해제된 Mac·앱 프로세스를 장악하거나 앱 코드를 바꿀 수 있는 공격자, 프로세스 메모리, 화면·클립보드 내용.
- 파일 크기와 보관 파일 이름에 포함된 날짜·확장자, 일반 모델 설정·로그. 파일명과 크기를 숨기는 기능은 없습니다.

Mac 분실에 대비하려면 FileVault도 별도로 켜세요. 앱은 FileVault 설정을 자동으로 바꾸지 않습니다.

검증: `.venv/bin/python tests/vault-smoke.py`, `NODE_PATH=/tmp/azimuth-dom/node_modules node tests/dom-smoke.cjs`. 자동 검증은 암호화·전환·세션·UI의 계약을 확인합니다. 실제 Touch ID·Mac 암호 인증은 사용자와 macOS 인증창의 상호작용으로 확인합니다. 모델 처리 흐름의 별도 검증은 `tests/smoke.py`입니다.
