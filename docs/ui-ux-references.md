# Local LLM Encoder 디자인·UI/UX 조사

조사일: 2026-11-12. 공식 제품 페이지·도움말·Apple 가이드를 직접 확인했다. 아래의 **확인한 패턴**은 출처의 제품 설명이고, **앱에 적용할 제안**은 코드와 사용 흐름에 맞춘 판단이다.

후속 구현에서는 사용자가 선택한 [Superwhisper 기록 화면](https://superwhisper.com/docs/get-started/history)의 구조를 적용했다. 왼쪽 메뉴, 검색 가능한 기록 카드, 카드별 원문·요약 전환과 음성 재생·복사·재처리를 제공한다. 기록별 편집·내보내기와 전체 메모를 분리했다. 1.3.0에서는 추가 요청에 따라 별도 비밀번호를 제거하고 Touch ID·Mac 로그인 암호의 시스템 인증 버튼만 제공한다. 아래의 비교·우선순위는 조사 당시 제안이며, 문장별 재생·요약 근거 연결·미니 녹음창은 이번 구현에 포함하지 않았다.

사용자 피드백에 따라 시각 스타일도 공식 화면의 무채색 회색 배경·카드, 넓은 메뉴 간격, 파란 동작 아이콘, 보라색 기록 아이콘에 맞췄다. 임의의 초록 색상과 장식 문구를 제거했다.

## 추천 방향

**Superwhisper의 빠른 녹음 조작 + MacWhisper의 기록 편집 + Granola의 문서 가독성**을 조합한다. 모델 설치 화면은 LM Studio의 기본·고급 설정 분리를 참고한다.

조사 당시 앱은 네이티브 녹음 헤더 아래에 웹 작업 공간을 넣은 880×700 패널이었고, localhost 화면에 녹음·파일·받아쓰기·요약과 영어 버튼이 섞여 있었다. 후속 구현은 기본 창을 1000×760으로 넓히고 기록 카드 중심으로 바꾸었으며, 공통 동작을 한글로 통일했다.

## 화면 구성 제안

1. **메뉴 막대 메뉴**: 녹음 시작/종료, 작업 공간 열기, 최근 기록, 보관함 잠그기, 설정, 모두 종료. 작업 중인 상태는 문자와 아이콘으로 함께 표시한다.
2. **미니 녹음창**: 마이크 이름, 경과 시간, 입력 표시, 중지 버튼. 중지는 녹음을 보관하는 동작으로, 폐기는 별도의 명령으로 구분한다.
3. **작업 공간**: 왼쪽 기록 목록 + 넓은 본문. 기본 본문은 `받아쓰기 / 요약` 탭으로 공간을 확보하고, 넓은 창에서만 나란히 비교한다. 선택한 파일 수와 일괄 작업 대상은 계속 보인다.
4. **설정**: 기본 모델 준비·입력 장치·자동 잠금처럼 자주 쓰는 항목부터 배치하고, 모델 파라미터와 프롬프트 편집은 별도 영역으로 둔다.

Apple은 메뉴 막대의 빠른 기능에 메뉴 사용을 우선하며, 팝오버에는 소수의 관련 작업을 담도록 권장한다. 따라서 큰 편집기는 크기를 바꿀 수 있는 작업 창으로 두는 구성이 적합하다고 판단한다. [Apple 메뉴 막대](https://developer.apple.com/design/human-interface-guidelines/the-menu-bar), [팝오버](https://developer.apple.com/design/human-interface-guidelines/popovers)

## 잠금 화면과 첫 설치

- **처음 만들 때**: `Touch ID` 또는 `Mac 로그인 암호로 열기` → macOS 본인 인증 → 무작위 비밀값을 키체인에 저장하고 보관함 생성. 앱 안에는 암호 입력란을 두지 않는다.
- **다시 열 때**: 같은 두 시스템 인증 버튼을 사용한다. 기존 보관함은 최초 인증 후 키체인 연결을 전환한다. 브라우저는 Mac 앱 열기만 제공한다.
- **표현**: `Touch ID / Mac 암호로 열기`처럼 실제 가능한 인증 수단을 쓴다. 취소했을 때는 잠긴 화면을 유지하고 입력 방식 선택으로 돌아갈 수 있게 한다.
- **잠김 상태**: 기록 제목·본문을 숨기고 녹음 버튼에 `보관함을 먼저 여세요` 이유를 연결한다. 별도 작은 배지로 상태를 알린다.
- **보호 범위**: `보관함에 암호화 저장`과 `내보내기`를 구분한다. 외부로 저장할 때만 일반 파일로 저장됨을 선택 지점에 표시한다. 녹음 중 임시 파일 제외 범위는 보안 안내에서 확인할 수 있게 한다.

Apple은 생체 인증에 대체 인증 경로를 제공하고, 민감한 접근의 용도를 명확히 설명하도록 안내한다. 위 문구와 배치는 이 앱의 키체인·브라우저 차이에 맞춘 제안이다. [LocalAuthentication](https://developer.apple.com/documentation/localauthentication/logging-a-user-into-your-app-with-face-id-or-touch-id), [개인정보 가이드](https://developer.apple.com/design/human-interface-guidelines/privacy)

| 상황 | 보여줄 내용과 다음 동작 |
| --- | --- |
| 아직 기록 없음 | `첫 녹음을 시작하거나 오디오 파일을 추가하세요.`와 두 동작만 제공한다. |

| 요약 중 | 사용 중인 서식, 생성되는 문서, 취소. 원문은 계속 읽을 수 있게 한다. |
| 모델 준비 중 | `음성 모델 / 요약 모델` 각각 준비 여부. 측정 가능한 다운로드만 진행률을 표시하고, 로딩처럼 측정할 수 없는 과정은 단계 이름을 표시한다. |
| 작업 실패 | 해당 기록에 원인과 `다시 시도`를 둔다. 원본 녹음과 사용자의 편집 내용을 보존한다. |
| 저장·내보내기 | 자동 저장 상태는 `보관함에 저장됨`. 일반 파일 생성 명령은 `내보내기…`로 통일한다. |

진행률과 단계 구분은 [Apple 진행 표시 가이드](https://developer.apple.com/design/human-interface-guidelines/progress-indicators)를 참고했다. 실제로 알 수 없는 남은 시간이나 진행률을 만들어 표시하지 않는다.

버튼은 `Start record → 녹음 시작`, `STT → 받아쓰기`, `Add → 파일 추가`, `Delete → 삭제`, `Copy → 복사`로 통일한다. 미완료 상태에서는 `왜 사용할 수 없는지`를 가까운 문장으로 설명한다.

## 시각 스타일 제안

- 본문은 밝은 중성 배경과 높은 글자 대비를 기본으로 하고 시스템 다크 모드도 따른다. 색상은 시스템 강조색을 기본으로, 빨강은 녹음·폐기에 제한한다.
- Mac에서는 시스템 글꼴과 SF Symbols를 사용한다. 한국어 문서는 15~16px, 줄 높이 약 1.65를 출발점으로 삼아 실제 긴 회의록에서 조정한다. 이 수치는 제안 값이다.
- 조작 영역은 촘촘하게, 문서 영역은 넓게 둔다. 반복된 카드 테두리·큰 로고보다 현재 기록의 제목과 내용에 시각적 무게를 둔다.
- 키보드 포커스를 보이게 하고 상태는 색상·아이콘·문자를 함께 사용한다. 복사·찾기 등 표준 명령은 익숙한 단축키를 유지한다.

## 구현 순서

**P0**: 한글 동작 명칭, 공통 상태 표시, 첫 설정·잠금 문구, 원문·요약의 읽기 폭과 탭, 일괄 작업 범위 표시. 기존 서버 기능으로 시작할 수 있다.

**P1**: 미니 녹음창과 작업 창 분리, 기록 검색, 모델별 준비 상태, 기본·고급 설정 분리. 창 관리와 검색 상태 처리가 추가된다.

**P2**: 문장별 재생 이동, 요약 근거로 이동, 수정본과 재생성 결과 비교. 받아쓰기의 구간 시간과 요약의 근거 정보를 저장하는 계약부터 확장해야 한다.

## 확인 범위

공식 문서와 공식 게시 이미지로 비교했다. 경쟁 제품을 설치해 실제 조작하거나 사용성 실험을 한 결과는 아니다. 사이트의 홍보 화면과 도움말 이미지는 서로 다른 버전일 수 있다. 가격·속도·정확도를 비교하거나 다른 제품의 저장 암호화를 검증한 자료가 아니다.

공식 이미지의 권리는 각 제품 제공자에게 있다. 저장소에는 이미지 복제본을 넣지 않고 출처 링크를 제공한다.
